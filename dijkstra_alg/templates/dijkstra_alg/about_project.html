Experimental university project

Exploring shortest paths
across a maritime network.

How can geographic data become a route? This university project explores that question by applying Dijkstra’s shortest-path algorithm to a shipping network stored in GeoJSON.

The aim is to connect graph theory with a working, interactive application: read geographic features, turn them into a weighted graph, calculate a route and make the result easy to inspect on a map.

01 / From a place to a path

How routing works

  1. Locate the places.Departure and destination names are geocoded through Nominatim to obtain their coordinates.
  2. Find nearby network points.A k-d tree matches each location to its nearest endpoint in the shipping network.
  3. Calculate a shortest path.Dijkstra’s algorithm explores directed connections and finds a path with the lowest total of the dataset’s stored Length0 weights.
  4. Draw the result.The chosen segments are joined in order and displayed as a sharp route above the background shipping lanes.

02 / Geography behind the map

Two datasets, distinct roles

Shipping network

The historical network contains 8,273 directed segments. Its metadata attributes it to Oak Ridge National Labs’ transportation network group, with a publication date in 2000.

Its endpoints include offshore waypoints as well as coastal connections. These segments provide the graph used for routing.

Port catalogue

The bundled catalogue contains 3,582 sea, river, lake and other port records. The highlighted circles use these recorded locations.

Port cards show the supplied name, country, code, type and coordinates. Missing information is labelled as not listed.

The catalogue and routing network are independent. A visible port does not guarantee a connected route to every other location.

03 / A quick guide

Using the map

  • Plan a route: enter two place names and select Find route. Adding a country can help distinguish places with similar names.
  • Explore ports: hover over a highlighted circle for basic details. Click or tap to keep its card open; close the card or tap elsewhere to dismiss it.
  • Adjust the view: use Map layers to show or hide ports and shipping lanes. Zoom, pan or enter fullscreen to explore.
  • Review the result: Show entire route brings the path back into view. Clear route starts a new search.
  • Make more room: minimize the planner using its arrow. On small screens, it minimizes automatically after a successful search.

04 / What the experiment covers

Scope & limitations

This application is designed for learning and experimentation. The current model uses historical data and does not evaluate weather, currents, tides, vessel draft, traffic or current navigation restrictions.

  • “Shortest” has a specific meaning: the result minimizes the network’s stored weights. It does not estimate sailing time, fuel consumption or voyage safety.
  • Location matching is simplified: nearest-point searches use squared longitude/latitude distance rather than a distance measured over the Earth’s surface.
  • Connections have direction: a route may exist in one direction but be unavailable in the reverse direction. Disconnected locations return a message.
  • Data has gaps: port metadata can be incomplete or outdated, and network points can be some distance from the requested place.
  • Some features are exploratory: the Fastest and Safest preferences remain placeholders. Map display and place searches require their external services to be available.

Further experiments

Possible extensions include geographic-distance matching, newer network data, clearer links between ports and network nodes, and additional routing constraints.
